# Security-40: forty interface claims grounded in OpenWrt vulnerability history

Status: active program, opened 2026-11-24. Progress:
[security-40/progress.md](security-40/progress.md). Claims: `claims/035`–`claims/074`.

This program is a separate queue from the
[24-package evidence program](next-program-20261122.md); it does not lift any
gate, hold or deferred decision recorded there. Where the two touch the same
surface (JS UCI hold, markup extractor gate, template-argument deferral), the
older gate still applies and is restated per claim.

## Goal

Create and fulfill forty small claims, each covering one high-value interface
whose source shape sits behind a published OpenWrt bug or security advisory on
recent versions (23.05 / 24.10 / 25.12 era, plus the 2018–2021 historical
layer). The point is detection-relevant evidence: does the analyzer observe
the shape that made the historical bug possible, at pinned real sources, with
controls — not a vulnerability guarantee and not a runtime exploit.

A claim may end `demonstrated`, `partial`, `unknown` or `blocked`. Finding an
apparently unpatched vulnerable shape in pinned source is a legitimate
high-value result, but it is recorded as a bounded source observation; any
upstream disclosure is a separate, explicit user decision.

## Advisory basis

Catalog captured 2026-11-24 in `work/security-40/` (outside the repo): 41
published GitHub advisories from `openwrt/luci` (22), `openwrt/openwrt` (9),
`openwrt/uhttpd` (8), `openwrt/packages` (2), plus security sections of release
notes v25.12.6 / v24.10.8 / v25.12.5 / v24.10.4, plus the historical layer:
CVE-2018-19630 (uhttpd CGI reflected XSS), CVE-2019-12272 (LuCI ≤0.10 command
injection), CVE-2019-19945 (uhttpd Content-Length signedness),
CVE-2019-25015 (LuCI SSID stored XSS), CVE-2020-7248 (libubox blobmsg JSON
stack overflow), CVE-2020-7982 (opkg checksum MITM), CVE-2020-28951 (libuci
UAF). Two rpcd fixes cited in v25.12.6 release notes (GHSA-q5gr-86pq-vvwr
symlink re-authorization, GHSA-r2w2-q7cw-cfp2 session-token tmpdir) were not
publicly retrievable via the advisories API at plan time; claims citing them
say so and use the release-note text plus pinned C source as the oracle.

Recurring classes, in observed frequency order:

1. ACL over-grant / misplacement (read scope carrying exec or wildcard file
   access; mutating ubus methods under read ACL) — ~10 advisories.
2. Command construction from request or UCI values in ucode/JS handlers and
   package shell scripts — ~8 advisories.
3. Stored XSS via lease files, UCI values and status rendering — ~8 advisories.
4. Path traversal / symlink / canonicalization mismatch — ~6 advisories.
5. HTTP ingress parsing (smuggling, type confusion, signedness, DoS) — ~8
   advisories.
6. C memory safety in core libs and helpers — ~6 advisories.
7. Service/procd environment and log-parse injection — ~3 advisories.

## Execution rules

Inherit [AGENTS.md](../AGENTS.md) in full. Additionally:

1. Sequential waves, sequential claims within a wave. At most one heavy
   CodeQL run (database creation or large query) at a time (host ~3 GB
   available RAM). Light source-oracle lanes (git fetch, Python inventory,
   no database creation) may run in parallel with one heavy run while RAM
   headroom allows; record peak memory where supported.
2. Disposable checkouts under `work/security-40/<claim>/`; never use
   `luci-fork` (carries unrelated fwlive work) or any dirty checkout as a
   source pin. Re-resolve and record full SHAs at execution; plan-time pins
   are observations.
3. Source-first oracle per claim: exact expected multiset, one valid positive
   and one eligible near miss, fixed before viewing analyzer output.
4. Local CodeQL only (`gh codeql` / CLI 2.27.4). Record command, exit, elapsed
   time, peak memory where supported, database and pack digests. No CI.
5. Each claim update: status transition only with its named evidence; edit
   the claim file to current state; append a dated line to
   `security-40/progress.md`; commit per claim or per small coherent batch.
6. A gate failure is a recorded stop (`blocked`/`unknown` with reason), never
   a silently skipped claim and never a fabricated result.
7. No runtime, reachability, taint, authorization or vulnerability claim from
   syntax/source-model/CFG observation. Apparent unpatched shapes are bounded
   source observations; disclosure is a separate user decision.
8. Reassess after each wave (8 checkpoints): carry forward only named new
   decisions; do not inflate claim count into coverage.

## Effort and stopping

Forty claims at roughly one focused lane each; expect several hours of
sequential execution. If the session must pause, `security-40/progress.md`
is the resume point: it records the last finished claim, the active gate and
the next eligible claim. Do not restart finished work; re-verify pins only.
