This is a bounded local macOS route and extraction observation, not a release, security-query, SARIF, consumer, device-installation, or full-package scan claim. The actual bytes were taken from the retained `luci-base.ipk` of [run 45513606386](https://github.com/lucas-albers-lz4/codeql-openwrt/actions/runs/45513606386), SHA-256 `1a2188f5206ce61c993fdcc451781a06994ae2175b489eef56595858ef22b363`, and staged under their installed-path-shaped names. This does not assert the package was installed on a device. The independent [inventory](../mvp-luci-base-ipk-inventory-20261125/README.md) fixes the 16 suffix-member identities and hashes; archive members were read directly, checked regular, checked for safe paths and checked against those hashes before staging. Staged hashes were checked again after extraction.

The pre-output [oracle](oracle.json) records each identity, IPK hash and expected route derived from the current routing code and actual member bytes. All 16 decisions matched with multiplicity: eight plain `ucode_extension`; seven markup `ut_markup_extension`; and `usr/share/ucode/luci/uhttpd.uc` markup `markup_tag_content`. All eight markup decisions have status `inconclusive` and reason `markup_not_modeled`; this is a routing diagnostic, not an assertion of semantic modeling. The `SuccessfullyExtractedFiles` query returned exactly the 16 expected identities once each and `ExtractionErrors` returned no rows. All eight commands in the [receipt](receipt.json) exited zero. These diagnostics do not prove AST accuracy or security coverage.

In particular the staged `template/header.ut` had the IPK SHA-256 `6fb25a4ddb6038a3ffc207906157db2503cc1bff7dd230fd588776cde329c02e`, distinct from clean pinned source SHA-256 `67132f2d1c1cf743f3e4ce11d660a5a2569b461804a63914061fe956171be6c2`; `version.uc` was the generated IPK member SHA-256 `9567da9ecf509e8a58cec8b09806d8a0bd3d3717fb9a8160c24ad3e1903a6fa8`.
